# st7789

ST7789-family SPI TFT driver. Panel geometry, offsets, MADCTL, inversion and
tearing-effect are config fields, so one class covers several panels. DMA pixel
streaming, backlight PWM. Implements [`DisplayPanel`](driver-interfaces.md).

| | |
|---|---|
| Target / option | `pico_toolset_st7789` / `PICO_TOOLSET_BUILD_ST7789` (ON) |
| Links | same shape as [ili9486](ili9486.md) |
| Example | `components/st7789/example/st7789_example.cpp` |
| Presets | `kElecrowCrowPanelPicoHmi28`, `kPimoroniPicoDisplayPack` |
| Boards | [CrowPanel](../boards/elecrow-crowpanel-pico-hmi-2.8.md), [Pico Display Pack](../boards/pimoroni-pico-display-pack.md) |

## Config -- `St7789Config`

| Field | Default | Notes |
|---|---|---|
| `spi_instance`, `pin_sck`, `pin_mosi`, `pin_cs`, `pin_dc` | -- | **must set**; there is no MISO field (the bus MISO belongs to touch/SD) |
| `pin_reset` | 255 | none = software SWRESET only |
| `pin_backlight` | 255 | PWM backlight |
| `width`, `height` | -- | **must set**, in the wired rotation |
| `col_offset`, `row_offset` | 0 | panel RAM is often larger than the visible area |
| `madctl` | 0x00 | orientation/colour order, panel- and rotation-specific |
| `tearing_effect_on`, `inversion_on` | false | |
| `spi_freq_hz` | 62.5 MHz | one clock for commands and pixels |
| `use_dma`, `dma_channel` | true, -1 | as [ili9486](ili9486.md) |

## Presets

| Preset | SPI / pins | Panel | Notes |
|---|---|---|---|
| `kElecrowCrowPanelPicoHmi28` | spi1: SCK 10, MOSI 11, CS 9, DC 8, RESET 15, BL 18 | 320x240, offsets 0/0 | `madctl` 0x70, inversion off, TE off |
| `kPimoroniPicoDisplayPack` | spi0: SCK 18, MOSI 19, CS 17, DC 16, BL 20, no reset | 240x135, offsets 40/53 | `madctl` 0x70, TE **on**, inversion **on** |

## API -- `St7789 : DisplayPanel`

`bool init(cfg)`, `set_window`, `write_pixels`, `start_pixels_dma`/`pixels_busy`/
`finish_pixels_dma`, `end_write`, `fill_solid`, `set_backlight`, `spi()`,
`width()`, `height()`. There is no live clock tuning (see [st7796](st7796.md) for
that).

## Gotchas

- Gamma/VCOM tuning tables are switched on `width`/`height` inside `init()`, with
  one validated branch per real panel: 320x240 and 240x135 only. A new size needs
  a bench-confirmed table, not a guess.
- `fill_solid()` stages a 320-pixel row (`uint16_t row[320]`); panels wider than
  320 would overflow it.
- `madctl` 0x70 is validated only for the two presets; other rotations need their
  own value.
- A 320x240 framebuffer is 150 KB -- most of an RP2040's 264 KB SRAM.

## Usage

```cpp
pico_toolset::St7789 lcd;
lcd.init(pico_toolset::configs::st7789::kElecrowCrowPanelPicoHmi28);
pico_toolset::BufferedDisplay drv(lcd, framebuffer);   // for Screen/widgets
```

Clients: PiCoMonitor (both boards), PicoBoot (CrowPanel).
Lineage: a consumer's fork of Pimoroni's MIT ST7789 driver, rewritten as a plain
config-struct component with no PicoGraphics dependency.
