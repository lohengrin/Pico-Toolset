# ili9486

480x320 RGB565 SPI TFT driver for panels where the controller sits behind a
16-bit shift-register bridge (the Waveshare 3.5" RPi LCD family). DMA-backed
pixel streaming, backlight PWM, live pixel-clock tuning. Implements
[`DisplayPanel`](driver-interfaces.md).

## Config -- `Ili9486Config`

No pin has a default. Fields: `spi_instance`; `pin_sck`, `pin_mosi`, `pin_miso`,
`pin_cs`, `pin_dc`, `pin_rst`; `pin_backlight` (255 = none); `spi_freq_hz`
8 MHz (commands/parameters); `pixel_freq_hz` 25 MHz (pixel streaming);
`use_dma` true; `dma_channel` -1 (auto-claim; set 0-11 to pin one -- the driver
claims it itself, the caller must not).

Preset values: spi1, SCK 10, MOSI 11, MISO 12, CS 8, DC 24, RST 25, no
backlight, 8 MHz / 25 MHz, DMA on.

## API -- `Ili9486 : DisplayPanel`

`kWidth` = 480, `kHeight` = 320 (static, kept for existing callers), `width()`,
`height()`; `bool init(cfg)`; the `DisplayPanel` overrides (`set_window`,
`write_pixels`, `start_pixels_dma`/`pixels_busy`/`finish_pixels_dma`,
`end_write`, `fill_solid`, `set_backlight`, `spi()`); and the extras
`set_pixel_clock_hz(hz)`, `pixel_clock_hz()`, `pixel_clock_actual_hz()` (what
`spi_set_baudrate()` actually achieved at the last `set_window()`; 0 before the
first). Tuning a different core than the blit loop is safe: the worst case is one
frame at a stale rate.

## Wire protocol

Command byte with D/C low; every register parameter 16 bits (`0x00` pad + value)
with D/C high; CS pulsed around every command and parameter (latches the shift
register); pixel data one continuous CS-low burst, unpadded. `spi_set_baudrate()`
is called *before* CS is asserted for the window. The init register sequence is
vendor-specific -- a stock ILI9486 sequence leaves the panel blank.

## Gotchas

- The DMA path drains the RX FIFO and waits out BSY like `spi_write_blocking()`;
  both are required before CS is handed to another device (see
  [shared SPI bus](../guides/shared-spi-bus.md)).
- Validated pixel clock: 33 MHz clean, 40 MHz+ corrupts; the preset's 25 MHz is
  conservative ([clocks](../guides/clocks-and-power.md)).
- A 480x320 framebuffer is about 300 KB; allocate it from PSRAM.
- Private members carry board-like defaults (`spi1`, pins 8/24/25); `init()`
  overwrites them, so they are harmless.

## Usage

```cpp
pico_toolset::Ili9486 lcd;
lcd.init(pico_toolset::configs::ili9486::kWaveshareRp2350PiZero);
lcd.fill_solid(0xF800);   // red
```

Clients: PicoDoom (DMA polling loop on core1), TOM6809 (`LcdRenderer`, per-scanline
blits), PicoBoot (LVGL).
Lineage: a validated SPI driver plus DMA enhancement (MIT).
