# st7796

ST7796U 480x320 RGB565 SPI TFT driver for landscape boards like the
Waveshare/SunFounder 3.5" panels. Implements [`DisplayPanel`](driver-interfaces.md)
and exposes live SPI clock tuning like [ili9486](ili9486.md).

| | |
|---|---|
| Target / option | `pico_toolset_st7796` / `PICO_TOOLSET_BUILD_ST7796` (ON) |
| Links | same shape as [ili9486](ili9486.md) |
| Example | `components/st7796/example/st7796_example.cpp` (colour cycle, 500 ms) |
| Presets | `configs::st7796::kWaveshareRp2350PiZero` (SunFounder 3.5" IPS, ST7796U + XPT2046) |
| Board | [Waveshare 3.5" RPi LCD (A) on the PiZero](../boards/waveshare-3.5-rpi-lcd-a.md) |

## Config -- `St7796Config`

| Field | Default | Notes |
|---|---|---|
| `spi_instance`, `pin_sck`, `pin_mosi`, `pin_miso`, `pin_cs`, `pin_dc` | -- | **must set**; `pin_miso` is carried because touch shares the line |
| `pin_rst` | 255 | none |
| `pin_backlight` | 255 | |
| `width`, `height` | -- | **must set** |
| `col_offset`, `row_offset` | 0 | |
| `madctl` | 0x00 | build with `St7796Orientation{...}.to_madctl_byte()` |
| `invert_colors` | **true** | panel-specific; not every ST7796U panel needs it |
| `spi_freq_hz` | 8 MHz | |
| `use_dma`, `dma_channel` | true, -1 | |

`St7796Orientation` fields: `row_address_decrement` (MY), `column_address_decrement`
(MX), `swap_row_column` (MV), `vertical_refresh_bottom_to_top` (ML), `color_order`
(`St7796ColorOrder::Rgb`/`Bgr`), `horizontal_refresh_right_to_left` (MH). COLMOD is
fixed to RGB565.

## Preset -- `kWaveshareRp2350PiZero`

spi1, SCK 10, MOSI 11, MISO 12, CS 8, DC 24, RST 25, no backlight; 480x320;
offsets 0; `madctl` = MV|BGR = 0x28; `invert_colors = true`; `spi_freq_hz` 132 MHz;
`use_dma = false`. Pins are carried over unchanged from the ILI9486 preset; the
whole preset is *validated* (PicoDoom, PicoBoot).

## API -- `St7796 : DisplayPanel`

The `DisplayPanel` overrides plus `set_pixel_clock_hz(hz)`, `pixel_clock_hz()`,
`pixel_clock_actual_hz()`. DMA is gated off above 80 MHz inside `init()`, so the
132 MHz preset always runs on the synchronous path.

## Wire protocol

Targeted boards put the LCD header behind a SPI-to-parallel bridge (confirmed from the SunFounder
panel's fbtft `ilitek,ili9486` driver, `buswidth=8`, `regwidth=16`): every command
and parameter byte is padded to 16 bits, and only the bulk pixel stream after RAMWR
is unpadded. Class structure follows [st7789](st7789.md); the register sequence
is ported from TFT_eSPI's ST7796 driver (MIT).

## Gotchas

- 132 MHz needs `clk_sys` 264 MHz **and** `clk_peri` tied to it; on the stock
  48 MHz `clk_peri`, `spi_set_baudrate()` caps at 24 MHz whatever is requested.
  The datasheet ceiling is about 125 MHz, so the preset runs 5.6% above spec --
  artifact-free on the validated panel ([clocks](../guides/clocks-and-power.md)).
- Touch on this panel inverts the horizontal axis relative to the ILI9486 panel
  ([xpt2046](xpt2046.md)).
- `invert_colors` is a per-panel requirement.

## Usage

```cpp
pico_toolset::St7796 lcd;
lcd.init(pico_toolset::configs::st7796::kWaveshareRp2350PiZero);
```
